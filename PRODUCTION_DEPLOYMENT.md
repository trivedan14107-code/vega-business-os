# Deploy Vega to Production (Vercel & Render)

## Deploy to Vercel (1-Click Serverless)

Vega is pre-configured with native `@vercel/python` serverless support via [`vercel.json`](file:///C:/Users/M%20Trivedan/OneDrive/Documents/ChatGPT/Hackathon-%201/vercel.json), [`api/index.py`](file:///C:/Users/M%20Trivedan/OneDrive/Documents/ChatGPT/Hackathon-%201/api/index.py), and [`requirements.txt`](file:///C:/Users/M%20Trivedan/OneDrive/Documents/ChatGPT/Hackathon-%201/requirements.txt).

### Option A: 1-Click via Vercel Dashboard (Recommended)
1. Go to **[https://vercel.com/new](https://vercel.com/new)**.
2. Select your repository: **`trivedan14107-code/vega-business-os`**.
3. (Optional) Add Environment Variables:
   - `GROQ_API_KEY`: Your Groq API key for autonomous planning.
   - `TOKEN_ENCRYPTION_KEY`: A 32-byte Fernet key (optional, auto-generated if omitted).
   - `GOOGLE_CLIENT_ID` & `GOOGLE_CLIENT_SECRET`: For Google Workspace integration.
4. Click **Deploy**. Vercel will build the Python serverless function and launch the web app with an instant HTTPS `*.vercel.app` domain!

### Option B: Deploy via Vercel CLI
Run:
```bash
npx vercel
```
Follow the prompts to link your project and deploy.

## Publish Vega on Render (Dedicated Persistent Server)

The repository also includes `render.yaml`, which creates an HTTPS FastAPI service and a
persistent encrypted disk for Vega's SQLite database.

## 1. Before deployment

- Put this project in a private GitHub repository. Never commit `.env.local` or
  `businessflow.db`.
- Rotate any Groq or OAuth secret that has appeared in a screenshot or chat.
- Keep the Render service name `vega-business-os`. If you rename it, update
  `APP_BASE_URL` and `ALLOWED_HOSTS` to the resulting HTTPS hostname.

## 2. Create the Render Blueprint

In Render, select **New → Blueprint**, connect the private GitHub repository, and use the
root `render.yaml`. Render will request these platform-owned values:

- `GROQ_API_KEY`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `OWNER_EMAIL` — the business owner allowed to sign in
- `TOKEN_ENCRYPTION_KEY` — a Fernet key generated by
  `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`

Render generates `SESSION_SECRET` itself. Do not reuse local development secrets.

## 3. Activate production Google OAuth

In Google Cloud Console, add this exact authorized redirect URI:

`https://vega-business-os.onrender.com/api/oauth/google/callback`

Set the OAuth consent screen to production and complete Google verification before inviting
users outside the configured test-user list.

## 4. Activate Slack (optional)

Add these Render environment variables: `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, and
`SLACK_REDIRECT_URI=https://vega-business-os.onrender.com/api/oauth/slack/callback`.
Add the same callback URL in the Slack app's OAuth settings, then redeploy.

## 5. Release check

- Open `/health` and confirm `{"status":"ok","service":"vega"}`.
- Sign in using `OWNER_EMAIL`.
- Connect Google Workspace and Slack through their buttons.
- Create one test meeting, approve it, and verify the Calendar event and notification.
- Confirm Render disk snapshots and service alerts are enabled.
